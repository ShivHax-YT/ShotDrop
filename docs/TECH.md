# ShotDrop — Technical plan

## Stack
Swift 6, SwiftUI + AppKit, menu bar app (`LSUIElement = YES`), XcodeGen project, macOS 14.0+. Distribution: Developer ID, not sandboxed for v1 (simpler file access). Keep the architecture sandbox-ready.

## How screenshots are detected
- Primary: file-level FSEvents with FileEvents, NoDefer, WatchRoot, and 50 ms configured notification latency. Actor-owned detection handles only direct, visible PNG/JPG/JPEG/HEIC children of the source folder. Event coalescing/drop flags trigger reconciliation; a moved/unavailable root stops detection with an actionable status.
- Readiness: at most ten observations across approximately five seconds, requiring two consecutive stable identity/size/mtime observations, a true screenshot-marker xattr, and a complete ImageIO image. File-descriptor reads reject symlinks and check identity before/after reading. Four candidates can be checked concurrently; no idle polling. Later filesystem events can reawaken exhausted candidates.
- Optional reconciliation: `NSMetadataQuery` with predicate `kMDItemIsScreenCapture == 1`. Initial gathering is suppressed; later URLs pass through the same validation and identity deduplication as filesystem hints. Missing Spotlight results never gate filesystem detection.
- Startup history and emitted files are deduplicated for the detector session by device/inode/birth time. Observation starts before the baseline scan, and creations during startup are distinguished by birth time. A future move/copy coordinator must prevent its own newly created output identities from entering the source pipeline.
- System screenshot location: read `defaults read com.apple.screencapture location` (default ~/Desktop). Offer (optional) to change it to a hidden inbox folder so the Desktop stays clean. That writes another app's defaults domain, so do it only with explicit user consent.
- Ignore the temporary file macOS writes while the floating system thumbnail is shown (it finalizes after the thumbnail disappears). Research: whether to recommend users turn off "Show Floating Thumbnail" in the Cmd+Shift+5 options for instant files.
- `ScreenshotDetector` is explicitly started/stopped and is currently exercised by synthetic tests only; app startup does not access Desktop. Wire it into the permission and complete copy/save flow before enabling user capture processing. The future app coordinator must stop/resume detection around display sleep.

## Clipboard
`ScreenshotClipboardPreparer` reads bounded encoded image data through a pinned, non-symlink descriptor off MainActor. The image path currently accepts verified complete PNG only (64 MiB encoded-data limit); JPEG/HEIC are never labeled PNG. Non-PNG screenshots may still use File mode. No full-size NSImage/TIFF conversion or lazy provider is used. Prepared immutable PNG bytes remain independent of later source moves or changes.

`ScreenshotClipboardPublisher` receives an explicitly selected pasteboard and writes one fresh `NSPasteboardItem`: Image has `public.png`, File has `public.file-url`, and Both has both types on that same item. File/Both require an explicit surviving saved destination or original, with identity and metadata revalidation off MainActor immediately before publication. A file URL references its current path; it cannot follow later moves or guarantee future access. There is no atomic transaction spanning filesystem mutations by other processes and pasteboard publication.

Item representation setup occurs before ownership changes and every setup/write result is checked. MainActor prepares current-host-only ownership and writes synchronously without an intervening await. Setup/preflight failures preserve prior ownership; a write failure after preparation may leave the clipboard cleared. The service does not read or back up the user's clipboard and promises no rollback. Only successful AppKit writes return a copied receipt. The `beforeOwnership` hook lets the future integration coordinator reject superseded work after asynchronous file revalidation and before any ownership change; ordering policy belongs to the pipeline integration coordinator.

Tests use uniquely named private pasteboards and injected writers, never the general clipboard. App startup still does not activate copying. Real Finder, rich-text, browser/app, after-quit, folder-permission, and cross-device behavior require separate QA. Both offers representations and cannot control which type a consumer chooses. Existing native labeled menu preference remains Image / File / Image and file, with system keyboard and accessibility behavior.

API availability is checked against the installed SDK with deployment target macOS 14: [writeObjects](https://developer.apple.com/documentation/appkit/nspasteboard/writeobjects(_:)) and item data setup date from macOS 10.6; [currentHostOnly](https://developer.apple.com/documentation/appkit/nspasteboard/contentsoptions/currenthostonly) ownership options date from macOS 10.12.

## Rename / move
`ScreenshotOrganizer` admits one transaction at a time into an explicitly enrolled app-private pool on the destination volume. Its nonblocking registry lock remains held across actor awaits, publication, and reset. Source and stage descriptors remain pinned; streaming reads enforce the 64 MiB payload ceiling even if the source grows, and partial writes cannot exceed the remaining allowance. Extended-attribute names and values (including resource forks and the output token) share a 1 MiB aggregate ceiling. Source ACLs, permissions, and flags are not inherited; fixed slots and cloned outputs use POSIX mode 0600. Outputs also inherit destination ACL entries under normal clone semantics, so mode 0600 alone does not imply that no other account has access; private slots must remain ACL-free.

`fclonefileat` publishes exclusively from the pinned stage descriptor, so replacing its pathname cannot redirect publication. Collisions retain the same lease and retry numbered names, including a collision arising inside the clone call. Clone support is required; unsupported, cross-device, full-disk, and permission failures retain the source with no pathname fallback. A source on another volume is copied into the destination-volume pool first. Separate physical-volume and disconnect/reconnect acceptance remain unverified. Originals are never deleted. Post-publication verification failures preserve the output as an unverified recovery artifact.

The fixed journal permits at most four registered destination-volume roots, one per persistent volume UUID, each containing exactly two precreated slot files: eight slots and four pool directories (12 pool entries), plus a registry directory with one lock and one journal bounded to 64 KiB. The aggregate slot allowance is 520 MiB logical payload/metadata; this is not a physical disk quota. Admission initially supports writable internal, nonremovable, nonejectable local APFS with a valid persistent volume UUID and advertised file-clone capability. Read-only, network, unsupported, or unknown capability states fail before any root reservation. Provider/cloud-managed paths and external volumes are not initially supported. An explicit reviewed ordinary-local-path attestation defaults to false and is bound to the canonical existing selected destination, its persistent volume UUID and directory inode/birth, and the registered pool identity. Known iCloud/File Provider paths are rejected even when attested. This is not complete provider detection and selecting a folder alone is not proof. One attestation per root can be explicitly replaced after revalidation without creating another root. Changing, removing, or replacing the selected destination pauses saving until re-review; date subfolders below the reviewed root remain supported. The actual clone operation remains authoritative. A persistent UUID is not an adversary-proof credential; duplicate or ambiguous volume identities fail closed. Root-registration intent is charged and synced before creation. Partial registration, retired slots, and offline roots remain charged; no replacement or automatic capacity expansion is permitted. An offline or moved pool blocks only its own destination volume while a different healthy registered pool may continue; corruption or uncertainty in the shared registry/lock/accounting blocks every pool. Startup reads only bounded known records and known child entries, never recursively scans or deletes legacy UUID stages. Initialization is explicit and requires separate legacy-accounting acknowledgment; the default service neither initializes nor repairs storage. Missing, corrupt, incompatible, uncertain, or exhausted state pauses saving before destination creation.

Schema 2 binds registry/root/slot identities to persistent volume UUID, inode, birth time, owner, and mode. Device numbers are checked only as live same-filesystem evidence, never as durable volume keys. Schema 1 has no silent migration or identity relearning. A simulated device-number change tests the abstraction; actual reboot/remount recovery still requires separate acceptance.

Slot states progress through clean, reserved, writing, prepared, publishing, and reclaiming. Every uncertain or unpublished transaction retires its slot; crash-interrupted states become durably retired without resetting bytes. Only a verified publication may reset the held descriptor after checking registered identity, private permissions/ownership, links, and known-output aliases. Reset removes copied metadata/resource forks, truncates payload, syncs the slot, then durably marks it clean. A creation-time `com.apple.provenance` baseline is treated separately as described below. Reset or journal failure retires the slot and remains separate housekeeping on the already verified saved receipt. No cleanup uses pathname unlink or directory deletion. Checked `fsync` calls establish requested filesystem flush ordering and fail on reported errors; they do not prove drive-cache persistence or power-loss recovery. No power-loss-safe guarantee is made.

This design assumes cooperative ShotDrop processes and a trusted app-private pool namespace. Hostile same-UID modification of the pool, aliases, or accounting is explicitly outside its guarantee; mode 0700, advisory locks, and journaling cannot prevent that attacker. Destination namespaces remain untrusted, so descriptor-bound exclusive publication and source preservation remain mandatory. Pool paths reject symbolic-link components, registry/root/slot identities are checked, and inherited extended ACLs are rejected. Automatic app processing stays disabled until exact-build QA/Review and reviewed enrollment/recovery are complete.

On this Mac, a freshly created file exposes an 11-byte `com.apple.provenance` value; removal or replacement reports success while descriptor readback remains unchanged. New slots therefore record this one OS-owned attribute's exact presence/absence and raw value in the registry, bound to slot identity. The 11-byte shape is an observed compatibility rule, not a documented Apple ABI. Only absent or 11-byte values are accepted; its name, terminator, and value (32 bytes when present) consume the existing 1 MiB metadata allowance. Source provenance is not copied over this baseline. Cloned output must expose the expected slot baseline, and reset/reopen must match it exactly; unexpected attributes, changed values, or unsupported behavior pause/retire rather than learn a new baseline. This is an explicit source-metadata exception, not a generic xattr ignore rule. Source contents and metadata remain unchanged. Supported-volume runtime checks must exercise baseline stability through writes, clones, reset, and repeated reuse; another filesystem that behaves differently fails closed.

Naming supports `{app}`, `{date}`, `{time}` and optional Gregorian `YYYY/MM` folders using the supplied time zone. Unknown/malformed tokens fail before I/O; filename components are sanitized and byte-limited. A pre-publication hook registers a fresh UUID output token with `ScreenshotDetector.ignoreOutput(token:)`. The token is stored in `com.macfleet.shotdrop.output-token`, copied by clone, and read through the detector's pinned descriptor; this prevents feedback despite the clone receiving a new inode. Supported source extended attributes are preserved within the aggregate cap, except this app-private output attribute (replaced with the new token) and the OS provenance attribute (the registered slot baseline is used). Source ACLs, modes, and flags are deliberately not copied. The source itself is unchanged. Neither service is activated from the app yet.

`ScreenshotSaveService` adds an explicit per-attempt save result around the organizer. Destination access must first be explained and user-approved by its caller; otherwise it returns an access-required result without probing folders. This is an intent gate, not a macOS permission grant. The future permission/integration flow owns the native folder selection and any system prompt. Neither service requests Screen Recording or changes system screenshot defaults.

`LocalScreenshotDestinationValidator` compares open-directory device/inode identities and traverses descriptor-relative ancestors. The source file’s parent is first bound to the declared source directory by device/inode identity. Source and output roots must be disjoint, including aliases and either ancestor direction. Missing independent destinations are checked using the nearest existing ancestor without creation; dangling symlinks, files, dot components, and access failures fail closed. Validation runs per attempt and again after the asynchronous pre-publication hook. This does not promise an atomic filesystem namespace transaction against external folder moves.

Save outcomes are saved, failed, or cancelled. Only the organizer's fully verified receipt produces saved. Structured POSIX codes survive both direct filesystem errors and Foundation directory-creation failures, so unsupported clone support, EXDEV, low space, denied access, verification failures, and collisions get specific recovery guidance. Failure preserves the original path and distinguishes a currently readable unchanged file snapshot from changed, unavailable, or uninspected originals. Original recovery checks identity, size, modification/change times, and mode; it is not a historical content backup. A surviving post-publication artifact stays an unverified recovery path, never a saved receipt or an automatic clipboard fallback.

Retry directly starts another save attempt, bypassing detector deduplication and leaving clipboard policy to the integration coordinator. Failure data supplies Retry, Choose Destination, and Reveal Original where applicable; Reveal Original is offered only after the original snapshot is verified available. `ScreenshotSaveRecoveryView` provides native text buttons and a selectable original path for the future failure presentation, but is not connected to the inactive shell yet. Keyboard/VoiceOver and native folder-permission interaction remain runtime acceptance work. Physical cross-volume acceptance remains blocked until a safe disposable volume can be exercised; injected EXDEV is not that evidence.

## First-run setup

One nonmodal setup window opens on first presentation and is always available through Finish Setup in the menu and Settings. Its four model-owned steps are welcome, destination, source access, and a gated test page. Not Now and the title-bar close control cancel pending work and leave processing inactive. The destination draft is persisted on close; a later Settings choice synchronizes the open draft and invalidates old checks. Only presentation history and the destination preference persist. Source access, directory identities, review evidence, and readiness never persist as booleans.

Setup reads an explicit `com.apple.screencapture` location preference without changing it. Absent or unrecognized values remain unknown; it does not silently substitute Desktop. A stored preference is only a hint: the user confirms the current Shift–Command–5 > Options > Save to choice before Continue attempts source access. Manually selecting a source does not change macOS settings. Source checks run off MainActor, open a no-follow directory descriptor, enumerate once without opening child files, and compare inode/birth/device identity before and after. Reopen retains the draft and prior live identity but clears access/readiness and rediscovers preferences only on explicit Continue. Changed preferences require explicit reselection; missing/replaced directories may be retried against the same identity without silently adopting a replacement. Late callbacks after Back, Not Now, selection changes, reopen, or cancellation cannot advance setup.

Destination inspection is read-only: it checks an existing nonsymlink directory, advisory write/search permission, supported volume/path rules, and source separation after source access. Advisory permission is not a successful write or reviewed local-path attestation. There is no setup probe file, folder creation, pool enrollment, legacy cleanup, or production attestation issuer. A missing default Pictures/ShotDrop folder stays unavailable until a separately reviewed creation/enrollment flow exists. The production readiness gate always denies. The test page requires distinct actual destination readiness, a complete pipeline, and a review bound to the exact source/destination identities; injected tests exercise this contract without enabling production processing. No Watching, Ready to capture, copied, or saved success follows a folder check.

The view uses native existing-folder panels, standard window chrome, semantic colors, scaled text, wrapping/scrolling paths, Back/Not Now and one default action, explicit permission recovery, and VoiceOver heading/picker focus. Step motion is 180 ms ease-out over 8 points and is disabled with Reduce Motion. Desktop/Documents/Downloads purpose descriptions explain folder checks; no Screen Recording permission is requested. Compilation and model tests do not establish native TCC, keyboard/VoiceOver, appearance, large-text, or motion acceptance; those remain live QA on the designated Desktop.

Frontmost app: `NSWorkspace.shared.frontmostApplication` sampled at detection time is only a best-effort naming hint. History remains future work (small JSON store or SQLite).

## Permissions
TCC "Desktop folder" access prompt when reading ~/Desktop. No Screen Recording permission is needed unless we add our own capture (ScreenCaptureKit) in v1.1.

## Risks
- The screenshot xattr is an identification heuristic rather than a documented capture-event contract. Missing/changed markers fail closed; originals remain untouched.
- Candidate-to-ready timings include readiness queue time; readiness sampling time is also returned independently. Native shortcut-to-file and file-to-clipboard timing still need real-capture acceptance measurements.
- Floating system thumbnail delays file creation by ~5 s.
- Ad-hoc signed debug builds lose TCC grants on each rebuild. Sign with an Apple Development identity (free personal team) so permissions stick.
